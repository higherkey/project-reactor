Project Reactor PWA: Development Roadmap & Technical SpecificationsThis document serves as a comprehensive project plan and technical specification for the development of a Progressive Web App (PWA) inspired by the 4 Player Reactor concept. It is structured to provide clear, modular instructions for AI-driven development tools, focusing on multi-touch responsiveness, cognitive game logic, and scalable scoring systems.1. Executive SummaryThe objective is to build a high-performance, local-multiplayer reaction game that functions seamlessly in a web browser while providing a native app experience. The game divides the screen into four quadrants, each serving as a player's interaction zone. The system must support concurrent touch inputs and deliver sub-16ms response feedback.2. Phase 1: Proof of Concept (POC)The POC focuses on the "Core Loop": an instruction is displayed, and the first player to tap their quadrant when the instruction is true receives a point.2.1 POC Game Modes (Top 15)Mode NameTrigger Condition Color MatchWord matches text color (e.g., "Red" written in red).Quick MathMathematical statement is true (e.g., 4 + 4 = 8).Odd One OutOne icon in a grid differs from the rest.Growing PainsCentral circle touches the quadrant boundary.Opposite DayTwo words are antonyms.Symmetry CheckTwo patterns are perfect mirror images.Prime PursuitDisplayed number is a prime number.Shape ShiftPolygon reaches a specific side count (e.g., Hexagon).Flash CountA brief cluster of dots is an even number.Clock WatchAnalog clock face matches the digital time string.Greater ThanEquation on the left is larger than the right.DirectionalVisual arrow points in the direction mentioned in text.Flag FinderFlag image correctly identifies the country name.Grid FillThe final empty tile in a grid is colored.Rhyme TimeTwo words displayed in the center rhyme.2.2 POC Scoring SystemThe POC utilizes a simplified win-condition state:Target Score Settings: Easy (5 pts), Medium (10 pts), Hard (20 pts).Winning Logic: The first player to reach the Target Score triggers the win screen.Global Instruction: One centralized instruction or image affects all four quadrants.3. Phase 2: Minimum Viable Product (MVP)The MVP expands the complexity of the game engine, introducing competitive depth and improved accessibility.3.1 MVP Game Modes (50 Total)Beyond the 15 POC modes, the MVP includes specialized categories such as Logic, Spatial, and Wildcards. Key additions include:CategoryFeatured Modes Advanced LogicBinary conversion, Logic gates (AND/OR/XOR), Set theory (Venn diagrams).Visual/SpatialNegative space identification, Shadow matching, 3D depth perception.KnowledgeChemical symbols, Planet order, History timelines, Music theory (notes).WildcardsThe Saboteur (freezing opponents), Collaborative Boss fights, Tilt controls.3.2 Advanced Scoring and MechanicsThe MVP introduces the "Friction Engine" to balance gameplay between different skill levels:Penalty System: Tapping when the condition is false results in -1 point and a 2-second "Lockout" where the player cannot tap.Dynamic Catch-up: If a player is trailing by 5+ points, their quadrant target area becomes 15% larger, or the instruction stays on screen slightly longer for them.Quadrant Chaos: Instead of static buttons, the hit areas utilize CSS Translation to drift or orbit within the quadrant, requiring spatial tracking.4. Technical Specifications4.1 Architecture StackFrontend: TypeScript, React (State), Tailwind CSS (Layout)PWA: Workbox (Service Worker), Web App ManifestHardware APIs: Pointer Events API (Multi-touch), Vibration API (Haptic Feedback)Rendering: Web Animations API / CSS Grid4.2 Key Logic ModulesInput Handler: Must use `pointerdown` events instead of `click` to eliminate the 300ms mobile tap delay. It must support `e.pointerId` tracking to ensure simultaneous taps are registered as distinct events.Instruction Generator: A centralized controller that cycles through a "Deck" of game modes. Each mode must implement a standard interface:interface GameMode {  id: string;  render(): JSX.Element;  validate(): boolean; // Returns true if the current state is "Correct"  difficulty: number;}4.3 AI Development ContextWhen generating code for this project via Gemini CLI or Antigravity, prioritize the following patterns:Modular Components: Keep each Game Mode in its own file under a `/modes` directory.State Immutability: Use a single source of truth for scores to prevent race conditions during simultaneous taps.Performance: Use `requestAnimationFrame` for any visual timers or moving hit areas to ensure 60fps on mobile hardware.5.
